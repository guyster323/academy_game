▖ 스토리 재료 3

13교시(10분)에는 결과물을 다시 만들지 않는다. 오늘 해 보며 겪은 것을 다섯 칸짜리 한 장으로 쓴다 — 그 다섯 칸 중 넷이 아래 셋에서 나온다.

1

불편했던 장면

완성된 HTML5 게임을 GitHub에 올렸는데, README에는 정지 스크린샷 4장뿐이었다. 저장소를 처음 여는 사람은 도트가 예쁜 것만 보고, 실제로 뛰고 쏘고 보스와 싸우는 장면은 상상해야 했다. “플레이 링크는 저 아래 있지만 아무도 안 누르겠지” 싶었다.

2

내가 정한 규칙

촬영용 자동 플레이는 주소에 ?demo=1 이 있을 때만 켜지고, 아무 키나 누르면 즉시 일반 플레이로 되돌린다.

  • 보스 체력은 실제 명중과 무관하게 약 8.7초 고정 곡선으로 깎는다 — 봇 실력과 무관하게 트레일러 길이가 일정하도록.
  • 한 장면 4초, 장면 전환은 0.5초 와이프, 총 8장면.
3

해보니 어땠나

  • 의외 ① 캔버스 게임은 밖에서 키 입력을 흉내내면 화면이 뚝뚝 끊긴다. 게임 코드 안에 자동 플레이 봇을 심는 게 정답이었고, 덤으로 ?demo=1 어트랙트 모드라는 진짜 기능이 생겼다.
  • 의외 ② 봇 난이도 조절에 세 번 다시 녹화했다. 보스 체력 0.5배는 1초컷, 1.8배는 70초 슬로그 → “고정 시간 곡선”으로 바꾸고서야 예측 가능해졌다.
  • 아직 못 맡김 봇의 조준·회피는 여전히 들쭉날쭉해서, “보스전답게” 보이는 컷 지점과 페이싱은 사람이 판단했다. GitHub이 커밋된 mp4를 다운로드 파일로만 준다는 것도 직접 부딪혀 알았다(→ GIF로 전환).
  • 시간 스크린샷을 “움직이는 트레일러”로 바꾸는 수작업(녹화·편집·인코딩)이면 반나절. 지금은 명령 한 줄, 약 4분이면 재생성된다.

▖ 제출 직전 점검

7개 중 5개 이상이면 제출. 막히면 새 기능은 추가하지 않는다 — 한 번 돌린 캡처와 제목 한 줄이면 제출된다.

  1. CLEAR

    내 환경에서 실제로 돌려 봤다

    node scripts/record-trailer.mjs 가 헤드리스 Playwright로 녹화 → PATH의 ffmpeg로 mp4/gif까지 무인 완주. ffmpeg가 없던 PC라 ffmpeg-static 을 PATH에 먼저 설치해야 돎(파일만 넘기면 AI가 안 도는 것은 정상).

  2. CLEAR

    실제 입력 1개 → 결과 1개를 캡처해 뒀다 (일반화·익명화)

    입력: 어트랙트 모드 플레이 세션(webm). 결과: cursor-slug-trailer.mp4(27초) + cursor-slug-hero.gif(7.7 MB). 화면에 개인정보·회사명 없음 → 익명화 불필요.

  3. CLEAR

    결과가 매번 비슷한 형식으로 나온다

    항상 1280×720 / H.264·yuv420p / 8장면 × 4초 / 0.5초 와이프 / 약 27초. 장면 순서는 스크립트의 events 배열로 고정.

  4. CLEAR

    빈 입력·이상한 입력에 안내가 나온다

    ffmpeg 미설치 시 즉시 명확한 에러, 스테이지·보스 타임스탬프를 못 잡으면 기본값으로 대체, 240초 하드 타임아웃으로 무한 대기 차단.

  5. CLEAR

    제출 형태를 정했다 — HTML 페이지

    이 문서를 저장소에 academy/index.html 로 커밋 → GitHub Pages가 /academy/ 로 렌더링. README의 ‘Academy 스토리 재료’ 버튼이 이 주소로 연결.

  6. CLEAR

    카드 제목 한 줄이 준비됐다

    아래 NAME ENTRY 참고.

  7. CLEAR

    13교시에 쓸 스토리 재료 3가지를 메모해 뒀다
